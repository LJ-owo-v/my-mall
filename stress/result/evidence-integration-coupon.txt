【问题一：积分丢失更新（#13 主体）—— 确认会触发】

  原实现（OmsPortalOrderServiceImpl 第 12 步）：
    memberService.updateIntegration(id, currentMember.getIntegration() - useIntegration)
    → updateIntegration 内部：record.setIntegration(传入值) + updateByPrimaryKeySelective(record)
    → 即"读积分 → 应用层算差值 → 整行回写"，【无任何守卫】

  触发路径（关键：可绕过 #14 的保护）：
    oms_cart_item 只有 PRIMARY 索引（无会员唯一约束）
      → 同一会员可以有【多个购物车行】（实测会员 11 有 2 行）
      → 用【两个不同购物车行 + 不同 SKU】并发下单
      → #14 的 occupyCartItems 抢占的是【不同行】→ 两个都成功 → 绕过 #14
      → 两笔都走到第 12 步扣积分：都读到 1000、各算 700、后写覆盖先写
      → 积分只扣一次（丢失更新）

  复现（修复前，真实接口并发）：
    会员 13 积分设为 1000；造 2 个购物车行（SKU110 / SKU111）
    并发发起两笔下单，各用积分 300
    结果：下单成功数 = 2，会员积分 = 700（应为 400）→ 丢失 300 积分

【问题二：use_integration 不落库（顺带发现的连带缺陷）—— 确认存在】

  代码顺序（原实现）：
    第 298 行  orderMapper.insert(order);                                    ← 先插入
    第 312 行  order.setUseIntegration(orderParam.getUseIntegration());      ← 后赋值
  → 赋值在 insert 之后 → use_integration 字段【永远不写入数据库】

  实测：订单 194/195 的 use_integration 均为 NULL（虽然积分确实被扣了 300）

  连锁影响（更严重）：
    cancelOrder / cancelTimeOutOrder 里判断
      if (cancelOrder.getUseIntegration() != null) { ...退积分... }
    → 字段恒为 NULL → 【取消订单永不退还积分】→ 用户资损

  背景：老项目 mall-swarm 同样如此（insert 在 224 行、setUseIntegration 在 236 行）
    → 属"照抄老项目"继承的既有缺陷（与 #17 同类）

【问题三：券核销先查后写 TOCTOU（#13 的另一半）】

  原实现（updateCouponStatus）：
    ① selectByExample 查 use_status=0 的记录      ← 先查
    ② setUseStatus(1) + updateByPrimaryKeySelective ← 后写（无 use_status 条件）
  → 并发下可能都查到 use_status=0 → 都执行更新（重复核销）

【修复（三处）】

  ① 积分原子扣减（新增 UmsMemberMapper.deductIntegrationSafely + XML）
       UPDATE ums_member SET integration = integration - #{points}
       WHERE id = #{memberId} AND integration >= #{points}
     · DB 侧自减，消除"读到旧值后覆盖"；WHERE 守卫保证不扣成负数；
     · 影响行数=0 → Asserts.fail("积分不足，无法下单") 触发整体回滚；
     · 扣减后 memberCacheService.delMember() 清缓存（原方法内部也做，保持一致）。

  ② use_integration 落库（把赋值移到 insert 之前）
     · 在"填充订单信息"阶段（insert 之前）setUseIntegration；
     · 未用积分时显式 setUseIntegration(0)（而非留 NULL）。
     → 既修数据不落库，也修"取消不退积分"。

  ③ 券核销改条件更新（新增 SmsCouponHistoryMapper.useCouponIfUnused + XML）
       UPDATE sms_coupon_history SET use_status = 1, use_time = NOW()
       WHERE coupon_id = #{couponId} AND member_id = #{memberId} AND use_status = 0
     · 把「检查」与「更新」合并为一条原子语句；
     · 影响行数=0 → 该券已使用/不存在 → 静默跳过（保持原容错行为）；
     · 退券路径 releaseCoupon 本身已是条件更新（WHERE use_status=1），未改动。

  附带：注入 memberMapper / memberCacheService（原类中未注入）。
